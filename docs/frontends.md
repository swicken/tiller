# Front ends and notifications

All front ends are clients of the same daemon, so closing one never stops the agents. A session, in the front ends, is one tree shown at a time, with a switcher between trees. A row of session tabs along the top of the window (the title bar strip in the app) switches trees with one click: hovering or focusing a tab shows a × that asks the same Close confirmation as the menus (a middle-click does the same), + opens New session, a right-click opens the root's actions menu and a double-click renames the tab in place. Cmd+Shift+[ / Cmd+Shift+] step to the previous or next tab, Cmd+Shift+1..8 select the Nth tab and Cmd+Shift+9 the last. Drag a tab, or press Cmd+Shift+Opt+[ / ], to move it; the daemon saves the order (in `state.json`) and every connected window follows it, and new sessions open at the right end. Closing the current session selects the tab to its right, or to its left when it was last. When the tabs do not fit, a mouse wheel scrolls them sideways and a faded edge marks tabs hidden past it. The sidebar's session list follows the same order. The **Rename session** pencil at the right edge of the switcher, or a right-click anywhere on it, edits the current tree's root title in place, even when a child is selected; clicking the rest of the switcher opens the session list. Any node's **More actions → Rename** edits its title in place where that menu was opened, in the title bar or in its sidebar row. In the editor, Enter saves, Escape cancels and clicking away saves; an empty name is ignored.

## The native app (macOS)

The app is a small Tauri v2 shell that hosts the browser UI in a native window and shows the number of blocked or waiting nodes as the Dock badge. To build it you need the Xcode Command Line Tools and Rust through Homebrew's rustup (how to install both is in [install.md](install.md)), with `export PATH=/opt/homebrew/opt/rustup/bin:$PATH` in the shell that builds it. The build runs `npm run ui:build` first, so the app always ships the current UI.

    npm run app:build    # unsigned src-tauri/target/release/bundle/macos/Tiller.app
    bin/tl-app           # opens that app, or runs `npm run app:dev` if it is not built

`tl` opens the app, or brings a running app to the front; `tl .` (or `tl <path>`) opens it on that directory's orchestrator, or switches a running app to it. On launch the app finds the daemon the way `tl` does (`TL_PORT`, then `~/.tiller/port`, then 7788). If none answers, it starts `bin/tld` detached, using the repo path that `tl` records in `~/.tiller/repo` the last time it started a daemon, then opens the UI with the admin token. The daemon keeps running when the app quits.

The app has a menu bar item: a dot that is green when nothing needs you, amber when a node is waiting or blocked, and red when a node's turn errored. Its menu lists the nodes that need you (clicking one selects it), Open tiller, and Do not disturb 1 h.

In the app, the New session dialog has a Choose… button beside Working directory that opens the native folder picker; the browser UI has only the text field, because a web page cannot read a folder's path.

## The browser UI

`npm run ui:build` writes the UI to `ui/dist`; the daemon then serves it at the URL `tl url` prints, which carries the admin token (the daemon log shows only the address, so the token stays out of `daemon.log`). It is the same UI the app shows: a sidebar with the tree, each node's live terminal, a last-message panel with the node's reported outcome, a Diff tab for worktree nodes in which you can add line comments and send them to the node as one message, and a status bar with today's total spend, the number of queued spawns and the do-not-disturb control. The status bar's **Updates** control checks published stable releases and shows the running version, missed release notes and any reason updates are unavailable. **Update vX.Y.Z** opens the same dialog when a newer release exists; applying it asks for confirmation because live agents are interrupted and resumed. The control shows “Updating…” during the rebuild and restart, and the page reloads when it reconnects to a different running commit. If the native app was rebuilt, quit and reopen Tiller. See [updating a checkout](releases.md#updating-a-checkout).

Each node's row shows its spend summed across its sessions, with the subtree total (Σ) on nodes with children. A trailing `+` (as in `$0.12+`) marks a figure that is only a lower bound because some of a Pi node's usage had no price; it carries into the subtree and today totals. The browser keeps its own toasts, a tab-title badge and a chime. A client that falls more than 8 MB behind on a node's terminal output (a stalled or backgrounded tab, say) stops receiving it; once its buffer drains it gets that terminal's current screen and carries on, so it never replays the backlog. `ui/README.md` covers developing the UI against a mock daemon.

In an agent node's terminal, Shift+Enter starts a new line in the prompt instead of submitting it: the terminal sends Ctrl+J (a line feed), which Claude Code, Pi and Codex all read as "insert newline". Enter still submits, Option+Enter is passed through unchanged (Pi uses it to queue a follow-up), and keys pressed during IME composition are left alone. Terminal nodes receive Shift+Enter as a plain Enter, as before. Links in a terminal, both OSC 8 hyperlinks and plain http(s) URLs, are clickable and open in the browser; other schemes such as `file:` are ignored.

## Working in the app

The sidebar shows your agent tree and lets you switch between sessions. Select a node to use its live terminal; the resizable **Details** drawer shows its model, effort, context usage and branch. Use **Transcript** to read a node's conversations with its parent, children and peers (tool calls are hidden unless you check **Show tool calls**) or its full transcript, including earlier sessions, or **Diff** to review a worker's worktree changes and send line comments back to it.

To switch an existing agent between Claude Code, Codex and Pi, open **More actions → Change harness…**. This stops the current process and starts a fresh conversation while keeping the node, its children and worktree. Earlier transcripts remain readable. Model, effort, preset and Claude permission overrides reset to the selected harness's defaults; review the confirmation before switching. See [harness switching](harnesses.md#change-an-existing-agents-harness).

By default, notifications appear when an agent needs your input or approval and when all agents in a tree finish. Individual completions and routine errors stay in the UI. Settings let you adjust notifications, quiet hours and shortcuts; node muting and do not disturb are also available. See [OS notifications](#os-notifications).

### Agent and Terminal tabs

An agent node's pane has an **Agent** tab, its agent's own terminal, and a **Terminal** tab, a plain login shell (`$SHELL -l`) for running quick commands yourself without spending the agent's tokens or context. The shell starts the first time you open the tab, in the node's directory (a worktree node's worktree, not the main checkout). A worktree node that is still armed, queued or creating its worktree refuses the tab with "worktree is not created yet"; open it again once the worktree exists. It runs as you: its environment has none of the node's identity (`TL_NODE_ID`, `TL_TOKEN_FILE` and the rest), so `tl` in it acts as the human. Switching tabs or nodes leaves it running; closing the node kills it, and so does a daemon stop, `tl reload` or `tl update` (opening the tab again starts a new one). If you `exit` it, reopening the tab starts a new one. The shell never changes the node's status or notifications, and an exited agent still has a working Terminal tab. A terminal node keeps its single Terminal tab. From the keyboard, the Cmd+K palette's **Terminal: <node>** and **Agent: <node>** entries switch the selected agent node's tab and focus it.

Agents cannot read or type into this shell, but they can suggest a command for it with the `suggest_command` tool. A pending suggestion shows as a `cmd` badge on the node's row (and "suggested command" on a collapsed parent), a dot on its Terminal tab, and a strip above the shell: `Agent suggests: <command>` with **Insert** and **Dismiss**, the agent's reason as the tooltip. Insert types the command at the shell's prompt without pressing Enter, so you can read or edit it first; it is available once the shell has printed its prompt. Insert types into whatever has the shell's foreground at that moment (vim, a REPL, an ssh session), not necessarily a prompt, so check the tab first. With the shell focused, Cmd+Enter inserts and Cmd+Backspace dismisses; either way the keyboard goes back to the shell, so Enter runs an inserted command. Each node holds one suggestion: a newer one replaces it, and Insert, Dismiss, closing the node or a daemon restart clears it.

### Questions

An agent that needs you to answer or decide something, and does not want the question to scroll away in its chat, raises it with the `ask_human` tool ([messaging](messaging.md#questions-for-the-human) describes the tool and how the answer travels back). The agent does not wait, and the question stays listed until you answer or dismiss it or the agent withdraws it. Nothing times out and nothing reminds you a second time.

**Where a question shows.** Three places, none of which scrolls with the chat:

- **A reminder for the session you are viewing.** It is one line in the row that holds the Agent, Diff, Transcript and Terminal tabs: the agent's name, the question, "+N more" when the session has others, and **Answer**. It shows the selected node's own question first, then questions an agent is waiting on, oldest first. In a narrow window it is a bar across the top of the pane instead. Neither form resizes the terminal. On the Terminal tab of a narrow window the suggested-command strip takes that place and the bar is not drawn.
- **The Needs you button** at the right end of the session tabs, with a count of everything waiting on you in every session: open questions, plus nodes stopped at a permission prompt or at a question in their own terminal. Cmd+J, the status bar's "N need you" and the Cmd+K palette's **Needs you** entry open the same panel.
- **Counts.** A session tab shows how many things in it need you, a node's row says "Question for you" (a collapsed parent says "1 question below"), and the status bar, the tab title, the Dock badge and the menu bar item count open questions together with blocked nodes.

A new question also raises a toast and an Activity entry, unless it belongs to the session in front of you in a focused window, where the reminder already shows it. Coming back after `daemon.digestAfterMinutes` away, the digest lists questions asked meanwhile.

**Answering.** The Needs you panel opens over the top right of the pane and is only as tall as what it holds. Items are grouped by session, the current one first. One question is open as a card; the others, and nodes waiting at a prompt in their own terminal, are short rows. Opening a row makes it the card; a row for a blocked node takes you to that node, because its prompt is answered in its terminal. The card shows the question, who asked and when, and one of two states: **Waiting on you** (the agent's work is on hold until you answer) or **Carrying on** (with what the agent is assuming meanwhile). **Background** opens the context the agent gave. Everything an agent wrote is shown as plain text; links in it are not clickable.

- A choice button answers at once, and sends along whatever you typed in the box as a note.
- **Send**, or Cmd+Enter in the box, sends your text as the answer. Enter starts a new line.
- **Dismiss** takes the question off your list without telling the agent. If the agent is waiting, it keeps waiting, so answer instead when you want it to move.

What you type is kept per question until you send or discard it, including when you close the panel. From the keyboard: Tab moves through the rows and the card's controls, Up and Down move between rows, Enter opens a row, and Escape closes the panel and returns focus to where it was.

**After you answer.** The card says what happened to the answer. "Waiting until <agent> is free" means the agent is mid-turn and reads it when the turn ends. "Not sent yet" means the agent is not running; it gets the answer when it starts again. "It may not have seen this" means the answer was sent without a receipt; it is not sent again, and the agent can still look it up. "Couldn't be delivered" means the agent was closed with no agent above it to receive the answer. Answers that have not arrived stay under **Not delivered**; delivered answers and dismissed or withdrawn questions are under **Done in the last day**.

If the answer could not be accepted, because the agent withdrew or replaced the question first or it was answered in another window or from the shell, the card says "Not sent", gives the reason and keeps your text so you can copy it or move it to the question that replaced the old one.

**When the asking node stops or closes.** A question whose node has exited stays open, and you can still answer it. When a node is closed, its open questions move to the agent above it, and the card says the answer will go there.

**From a shell.** `tl questions [--all]` lists open questions with numbered choices, `tl answer <id> [TEXT] [--choice N|LABEL]` answers one, and `tl dismiss <id>` drops one. They work with no window open. Inside a node they are refused, since only you may answer; a node's Terminal tab runs as you, so they work there.

## Inside a node: the band and slash commands

The tiller mod draws a one-line band above Claude's prompt: in a child, `↑ parent` and `⌂ root` buttons, which switch an attached client to that node, and the child that needs you, if any. It also shows in-session toasts when a child needs you, finishes or errors. The mod draws none of this while the app or a browser is attached, because their sidebars already show it.

The mod adds four slash commands: `/tl-list`, `/tl-spawn <title> :: <prompt>`, `/tl-send <id> <text>` and `/tl-read <id>`. They call the same handlers as the MCP tools every Claude node has. How the mod works is described in `mod/README.md`.

## OS notifications

The daemon is the only sender of macOS notifications, so the app and the browser never double up. By default, the daemon notifies only when an agent needs approval or an answer, or when all agents in a tree finish. An actionable notification is titled with the node (its session as the subtitle, when different) and says what it needs, for example `Needs approval: Bash touch /tmp/x`. Individual completions, exits and routine turn errors are silent; errors remain visible in node status and session history. An error that leaves an agent asking for input or approval still produces a needs-you notification. It stays quiet when a focused window (app or browser tab) has that node selected, and throttles individual events to one per node and kind every 5 seconds. Tree summaries follow completion edges, so a short new work cycle can still produce its own summary.

A question an agent raises with `ask_human` raises one notification at the needs-you level, titled with the node and reading `Asks: <question>`. The same rules apply: none for a muted node, during do not disturb, or while a focused window has that node selected, and a banner without sound in quiet hours. It is not repeated while the question stays open; the counts and the [reminder](#questions) are what persist. Clicking it selects the node, where the reminder is on screen.

An agent's request for your approval (a close, merge or terminal write) also raises a notification, titled `Approval needed` with the first line of the request, at the `notifications.kinds.approval` level. It is not tied to a node, so selecting a node does not silence it, but it is skipped while a focused window is open, since that window shows the request. Do not disturb silences it, and quiet hours leave it a banner without sound. Each request has its own banner, and clicking one only brings the app forward. The request stays pending until answered or expired, and a window that connects or reconnects meanwhile, such as a reloaded tab or the app waking from sleep, is shown it on connecting. Answering in any window dismisses it in all of them.

With `terminal-notifier` installed, a notification replaces the node's previous one, plays a sound where its level says so, and clicking it runs `tl select <id>`, which shows the node in the app (opening it if it is built). Without it the daemon uses `osascript` notifications, which cannot be clicked. `TL_TERMINAL_NOTIFIER` overrides the `terminal-notifier` path, and `TL_TERMINAL_BUNDLE` overrides the app a click activates when the native app is not connected (otherwise it is derived from `TERM_PROGRAM`). terminal-notifier 3.1.0 has no time-sensitive option, and its `-ignoreDnD` is documented as usually doing nothing, so needs-you and approval notifications are not marked time-sensitive. Its `-action` buttons are not used either: they keep the process waiting for an answer, and the useful action, approving, would answer for the human.

The `notifications` config keys set the level for each kind (needs-you, errored, done, exited and approval), a per-tree summary in place of per-agent completion notifications, and quiet hours; they are listed in [config.md](config.md). During quiet hours everything is silent except needs-you and approval, which become a banner without sound. `treeDoneSummary` defaults to true: one notification, "tree <title> finished: N succeeded, M failed", replaces the per-agent done and exited ones once every agent in the tree, including the root orchestrator, is done or exited. Shell terminals do not count. Queued or armed agents, pending launches, running gates and failed gates awaiting retry prevent the summary. Failed means the turn errored or the node reported a failed outcome. Retained done or exited agents count in the summary. New work, a pending launch, a restart or a gate attempt rearms the tree for its next completion; session shutdown and repeated completion or exit events do not repeat the summary. A failed gate waits for a fresh final failure report or a successful retry; a successful gate waits for its new outcome to be recorded. A retained outcome from before that attempt does not finalize it.

The root's `notifications.kinds.done` level controls its tree summary. Set it to `silent` to suppress summaries. Explicit `errored` and `exited` levels remain supported; disabling `treeDoneSummary` restores individual done and exited notifications at their configured levels. Muting, focused selection, do not disturb and quiet hours still apply; a suppressed summary is not replayed later. The daemon log has one line per notification, sent or suppressed and why.

## Mute and do not disturb

`tl mute <id>` and `tl unmute <id>`, or the bell button on a row, stop and restore one node's notifications; a muted row shows a crossed-out bell, and the mute is kept across restarts. `tl dnd [on|off|1h|30m]`, the "do not disturb 1 h" button in the status bar or the menu bar item stop all notifications until turned off, or for the time given. Do not disturb is not kept across a daemon restart. The status bar shows the time left, and the Dock badge still counts.
